查询指定日期入库成功账户列表

GET /openApi/billFutureApi/queryInsertSuccessAccountList?tradingday=20261008
请求位置Query String
响应类型Result<List<String>>
数据源multi-inside
数据表bill_future_settle_processing_log

请求参数

字段位置类型必填默认值说明
tradingdayQueryString是—指定交易日期；项目通常使用 yyyyMMdd 格式，例如 20261008。
accountTypeQueryString否期货账户类型，按完全相等条件查询。
logTypeQueryString否对账单数据日志类型，按完全相等条件查询。
logStatusQueryString否Success日志状态，按完全相等条件查询；实体约定值为 Success 或 Failed。

查询逻辑

服务使用以上 4 个条件查询处理日志，提取 accountId 后在应用层去重并返回。每次写入处理日志前会先删除相同交易日、相同账号的旧日志，因此正常情况下每个账号每天仅保留最新一条记录。等价筛选条件如下：

SELECT account_id
FROM bill_future_settle_processing_log
WHERE tradingday = #{tradingday}
  AND account_type = #{accountType}
  AND log_type = #{logType}
  AND log_status = #{logStatus}

接口对最终账户编号执行 distinct；当前查询未声明排序，返回顺序不构成接口承诺。

请求示例

GET /openApi/billFutureApi/queryInsertSuccessAccountList?tradingday=20261008

GET /openApi/billFutureApi/queryInsertSuccessAccountList
    ?tradingday=20261008
    &accountType=期货
    &logType=对账单数据
    &logStatus=Success

成功响应示例

{
  "success": true,
  "message": "",
  "code": 200,
  "result": ["80000001", "80000002"],
  "timestamp": 1791475200000
}

入库处理规则

ControllerBillFutureApiController
请求体BillFutureSettleIngestRequest
响应数据BillFutureSettleIngestResult
处理日志bill_future_settle_processing_log
这是全量快照接口。 服务会先按顶层 tradingday + accountId 删除 13 张业务表中的旧数据，再分别写入本次各数组。某数组为 null、缺失或空数组时，该表对应账号和交易日的旧数据仍会被清空。
  • 顶层 tradingday、accountId 均不可为空。
  • 每条明细的 tradingday、accountId 必须与顶层值完全一致，否则整个请求失败并回滚。
  • 数组中不可包含 null 元素。
  • 客户端传入的明细 id、insertTime 会被服务端清空，由数据库重新生成。
  • 13 张表在同一事务内处理，任一表写入失败时整体回滚；批量写入批次大小为 1000。
  • 账号数据全部入库成功后，Controller 写入一条 Success 处理日志。
  • 入库 Service 抛出运行时异常时，Controller 写入一条 Failed 处理日志，logInfo 保存异常消息，随后继续抛出原始异常。
  • 处理日志保存前，Service 先按 tradingday + accountId 删除旧日志，再插入最新日志；删除和插入位于同一事务中。
  • 处理日志固定使用 accountType=期货、logType=对账单数据，同时记录日志时间和 yyyyMMdd 格式的日志日期。
  • 鉴权头由实际部署的网关或 Spring Security 配置决定，Controller 本身未声明额外请求头。
事务边界说明： 账号业务数据先在入库 Service 的事务内提交，处理日志随后由 Controller 单独写入。成功日志写入异常不会回滚已经提交的账号业务数据；失败日志写入异常不会覆盖原始入库异常。

入库异常说明

场景服务端消息结果
请求体为空入库请求不能为空整个事务不执行。
资金账号为空资金账号不能为空整个事务不执行。
交易日为空交易日不能为空整个事务不执行。
任一数组包含 null{业务名称}数据不能包含空记录整个事务回滚。
明细账号或交易日与顶层不一致{业务名称}数据的交易日或资金账号与请求不一致整个事务回滚。
数据库删除或写入失败由统一异常处理器返回具体错误13 张表整体回滚；Controller 尝试写入 Failed 日志后重新抛出原异常。
成功处理日志写入失败期货对账单处理日志入库失败接口抛出异常，但此前已提交的账号业务数据不回滚。
失败处理日志写入失败仍以原始入库异常为主日志异常附加到原异常并写入服务日志，不覆盖原始失败原因。

HTTP 状态码与异常响应外形由项目统一异常处理器及网关配置决定；业务失败的常规 Result 结构通常使用 success=false、code=500。
